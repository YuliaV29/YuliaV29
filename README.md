## How I work

- **Targeted fixes over rewrites**: I change what's needed and leave working code alone
- **Native Shopify first**: metafields, Flow and Functions before adding another app (and another script on your pages)
- **Performance and accessibility by default**: Core Web Vitals, keyboard navigation, focus management, color contrast
- **Clear scope before code**: technical scope, edge cases and a QA checklist up front, so launch day has no surprises
- **Design-aware**: a graphic design background means I care about spacing, hierarchy and the details that make a layout feel finished
- **Marketing-aware**: I understand SEO, SEM and email/social funnels, so I build features with the merchant's goals in mind, not just the ticket
- **Staying current**: attended Shopify DOTDEV2026 in Toronto; following what's next for Liquid, metaobjects and AI in the Shopify ecosystem

## Working in your repository

- All code lives in the repository: every change is committed and versioned, so nothing gets lost and any change can be traced or rolled back
- Before critical updates we always back up the theme, so there's a ready restore point if anything goes wrong
- One branch per task; pull requests with a description, screenshots or recordings, and test steps
- Changes are previewed on an unpublished theme before anything goes live
